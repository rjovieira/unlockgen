unlockgen

A free, open-source Huawei unlock code generator for routers, modems and dongles. Enter the device IMEI; the codes are computed in your browser.

15 digits. Printed on the label under the battery or the underside of the router, on the box, and shown in the device web UI under Device Information.

Which code do I type in?

Huawei shipped four code-generation algorithms over the years, and nothing in the IMEI says which one your device uses — so all four are computed. Try them in the order shown. One will be accepted; the rest will be rejected.

CodePurposeNotes
V1SIM unlockThe oldest scheme. Early E-series dongles.
V2SIM unlockThe most common. Widely used across dongles and routers.
V3/201SIM unlockNewer firmware. Also called “v201” in older tooling.
FlashFirmware flashingNot an unlock code — it authorises firmware writes.

Attempt counters are real. Most Huawei devices allow around ten wrong unlock attempts before disabling the unlock function permanently. Four codes is well within that budget — but do not brute-force beyond them.

The Flash code is not an unlock code. It authorises firmware writes, and a bad flash bricks the device. Do not use it unless you know why you need it.

Which devices does this work on?

These four algorithms are the ones Huawei used while unlock codes were still derived on the device — broadly the hardware of 2008 to 2015. That covers the E-series USB dongles and mobile hotspots and the B-series home routers of that era, sold under carrier names worldwide.

Nothing in an IMEI identifies the model, so this is a description of a period rather than a compatibility list, and there is no way to tell in advance whether a particular unit is in scope. The cheap test is simply to generate the codes and try them.

Huawei moved to server-side, per-device unlock codes on later hardware, from roughly 2015 onwards. If none of the four codes are accepted, the device almost certainly uses that scheme — and no offline generator, this one included, can produce its code.

How the codes are derived

The unlock code is not stored on your device. It is computed from the IMEI by a keyed algorithm, and the same algorithm runs in the firmware to check what you type — which is why a code can be worked out offline at all.

V1 and Flash are the simplest: a hardcoded key is hashed, a slice of that hash becomes a salt, the IMEI is hashed with it, and the 16-byte digest is folded down into eight digits. The two differ only in the key — one for unlocking, one for authorising firmware writes.

V2 and V3/201 are not single algorithms but families of seven. A checksum of the IMEI picks which one to use, so two IMEIs one digit apart can be handled by completely different code. The seven techniques are a weighted digit sum, a CRC-32, digits harvested out of an MD5, a salted-MD5 fold, a substitution cipher over the XORed halves of the IMEI, two concatenated words of a SHA-1, and an MD5 taken over a 128-byte buffer scrambled out of the IMEI.

Two details look like bugs and are not. Huawei's CRC-32 table holds the same 256 values as the textbook table but in a scrambled order, so it cannot be generated from the usual polynomial and has to be embedded verbatim. And no code may begin with a zero, so every one of the fourteen slots carries its own fixup for that case — which is where most of the awkwardness in the implementation lives.

The full slot-by-slot breakdown is in the repository README.

Questions

Which of the four codes do I type into my Huawei router?

Try them in the order shown. Huawei shipped four code-generation algorithms and nothing in the IMEI reveals which one your device uses, so all four are computed. V2 is the most common across routers and dongles. The Flash code is not an unlock code — it authorises firmware writes.

Is it safe to try all four unlock codes?

Most Huawei devices allow around ten wrong unlock attempts before permanently disabling the unlock function. Four codes is well within that budget, but do not guess beyond them.

None of the codes work. What now?

Huawei moved to server-side, per-device unlock codes on hardware from roughly 2015 onwards. If none of the four codes are accepted, the device almost certainly uses that scheme, and no offline generator can produce its code.

Is my IMEI sent to a server?

No. The codes are computed by JavaScript in your own browser. There is no server, no analytics and no network request after the page loads, and the IMEI is never written to the URL, browser history or storage.

Where do I find my Huawei device IMEI?

It is the 15-digit number printed on the label under the battery or on the underside of the router, on the box, and shown in the device web interface under Device Information. Over an AT-command serial interface, AT+CGSN returns it.

Privacy

Every code is computed by JavaScript running on this page. Your IMEI is never sent anywhere — there is no server, no analytics and no network request after the page loads. Once loaded, the page keeps working with the connection off.

Still, treat your IMEI and its codes as private: given a known device model, a code narrows the IMEI down to a range small enough to brute-force, so publishing either one effectively publishes both. That is also why this page never puts an IMEI in the URL.

Verify it yourself

The page runs the same test vectors that ship inside the Python script — every one of the fourteen algorithm slots, both slot selectors, the awkward leading-zero and padding branches, and one end-to-end IMEI.

The generator is also cross-checked against unlockgen.py on every commit, over tens of thousands of IMEIs, by tests/parity.mjs.

Prefer the command line?

The Python original is a single dependency-free file:

$ curl -O https://raw.githubusercontent.com/rjovieira/unlockgen/main/unlockgen.py
